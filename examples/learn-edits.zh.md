## 逐类变化（都附原文）

- **删掉空话开头**
  - 前："在进行SFT之前，数据质量至关重要。高质量的数据能够显著提升模型表现，而低质量的数据则可能导致各种问题。"
  - 后：整段删除，改从一件具体的事开头："上个月我训了一版 7B 的 LoRA，loss 漂亮得不像话，输出却在句尾一直复读。"
- **泛泛的问题清单 -> 一个具体的坑**
  - 前："常见的数据问题包括格式不一致、标注错误以及缺失结束符等。"（三项并列，没有一项展开）
  - 后：只留"缺失结束符"，还原成一次排查过程："我先怀疑学习率，砍半重跑，白烧了一天。第三天才去翻数据——回答末尾根本没有 EOS。"
- **加入你自己的经历、数字和代价**：7B、LoRA、"上个月"、"白烧了一天"、"第三天"、"20 条样本"。你还保留了自己走过的弯路（先怀疑学习率），没有只给正确结论。
- **"应当重视"变成你的做法**
  - 前："我们应当重视数据的检查与清洗。"
  - 后："开跑之前，先随便抽 20 条样本，把最后几个 token 打出来看。"
  - 原来是一句态度，现在是一个动作，别人明天就能照做。
- **立场写得更硬**
  - 前："这些问题往往会影响训练效果，需要在训练前加以排查。"
  - 后："不看这一步，调再多超参都是在猜。"
- **结尾换了**
  - 前："总之，只有做好数据准备工作，才能为后续的训练打下坚实的基础。"（总结加升华，删掉也不损失信息）
  - 后：用一句边界声明收尾："当然，这只是我在单个模型、单个框架上的经验。换了模板，坑可能在别处。"
- **语气**：从"我们 / 应当 / 能够 / 加以"换成"我 / 砍半 / 白烧 / 复读 / 翻数据 / 不像话"，是口语的第一人称。

## 我推断的规则

1. **不用"X 至关重要"开头，先写一件发生过的事。** 最好带上结果和反差。（证据：开头对照；置信度：中高）
2. **一篇只讲一个具体的坑，不列"常见问题"清单。** 并列项没展开时，选一个展开。（证据：第二段对照；暂定）
3. **把"应当 / 需要"改写成"我现在的习惯是……"，并给出可以执行的动作和数量。**（证据："重视检查"->"抽 20 条、打印最后几个 token"；中高）
4. **保留走过的弯路和代价。** 写出先怀疑了什么、花了多久，不只写结论。（证据："先怀疑学习率……白烧了一天"；暂定）
5. **立场用不看这一步会怎样来表达，不用"往往会影响"这类缓冲词。**（证据：第四条对照；暂定）
6. **结尾不做总结升华，改成一句适用边界。** 写"这只是我在……上的经验，换了……可能不同"。（证据：结尾对照；中高）
7. **用"总之"收尾、写"坚实的基础"这类话，都要删。**（证据：结尾对照；暂定，只出现一次）

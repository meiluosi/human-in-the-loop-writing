# 做 SFT 之前先查数据，别急着调超参

（备选标题：
1. loss 很漂亮，输出却停不下来：一次 SFT 排查记录
2. 微调效果不好，先别动学习率
3. 我白跑了一轮才发现，问题根本不在超参）

上个月我用 LoRA 微调一个 7B 模型，2000 条数据。第一版跑完，loss 曲线很好看。但一试输出，每条回答的末尾都在无限重复，停不下来。

这个现象你要是碰到过，大概会和我做同样的事：去调超参。

## 我先砍了学习率

loss 好看、输出有问题，我的第一反应是学习率可能有问题。于是我把学习率砍半，重跑了一轮。

白跑了。

【作者补：砍半之后重跑的结果长什么样？是重复照旧，还是换了种花样？一两句话就行，越具体越好。】

## 三天之后，问题在数据里

之后又排查了三天，最后发现：我的训练数据里没有加 EOS。

加上 EOS 重新训练，末尾无限重复的问题消失了。

【作者补：这是整篇最值钱的一段。你是怎么发现的？是看了哪一条日志、解码了哪个样本，还是别人一句话点醒的？写下那一刻，再写这三天里你排查过哪些方向。我没有这部分信息，所以没替你编。】

## 为什么 loss 看不出来

这里是我的理解，发文前请你核对一下是否符合你的实际情况：

没有 EOS，模型在训练里从来没见过"这句话到这里就结束了"。它学会了怎么把答案写出来，没学会什么时候停。推理时它写完正文，没有任何信号告诉它该停，就接着往下生成，直到撞上最大长度。

而 loss 是在训练数据的 token 上算的。数据里缺的那一个结束符，不会让 loss 变难看，它只是不存在。所以曲线很漂亮，问题藏在曲线够不到的地方。

（待核实：不同框架和 chat template 对 EOS 的处理不一样，有的会自动补，有的不会。这句话是否适用于你当时的训练设置，请按你的实际环境改。）

## 超参好改，数据难查，所以我们总先动超参

学习率是一个数字，改一下，重跑，等结果。动作很小，感觉也很"专业"。

查数据要打开样本，一条一条看，看格式，看拼接后的样子。这个活儿又枯燥又没有成就感。

但我这次的经历是：改数字花了一轮算力，什么都没解决；而真正的问题，在一条样本解码出来的末尾就能看见。

所以我现在的想法是：效果不好时，先检查数据和格式，再动超参。

## 动手之前，我会先看这几样

下面是我的候选清单，【作者补：删掉你实际不会查的，补上你真会查的。这份清单应该是你的，不是通用的。】

- 随机抽几条样本，tokenize 之后再解码回文本，看结尾有没有 EOS
- 看拼接出来的完整输入，和模型期望的 chat template 是否一致
- 看 label 的 mask：该算 loss 的部分有没有算，不该算的有没有算进去
- 看有没有被截断：超长样本的结尾是不是被直接切掉了

这几样都是几分钟的事，比重跑一轮便宜得多。

## 什么时候该先看学习率

也别矫枉过正。如果训练曲线本身就有问题，比如发散了，或者上下震荡得厉害，那先看学习率仍然是合理的。

我说的是另一种情况：曲线很正常，甚至很好看，但输出不对。这时候更该怀疑的是喂给模型的东西，而不是怎么喂。

## 下次出问题时

下回你的 SFT 结果不对劲，在改任何一个数字之前，先抽一条训练样本，tokenize，再解码，看看结尾。

这一步我上个月要是做了，能省掉一轮算力和三天时间。
